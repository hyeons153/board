# LONGBOARD LIFE

퇴근 후 강변에서 시작하는 롱보드 커리어 시뮬레이션. React·TypeScript·Vite로 메뉴와 편집 화면을, Phaser 4로 도트 스팟·라이더·경기 재생을 구현했습니다. 훈련과 경기는 렌더링과 분리되어 서버에서 계산됩니다.

## 로컬 실행

Node.js 20.19 이상, 22.12 이상 또는 24를 사용합니다.

```sh
npm ci
npm run dev
```

콘솔에 표시되는 주소(기본 `http://127.0.0.1:5173/`)를 엽니다. Neon 설정 없이도 로컬 서버의 `.longboard/`에 게스트 커리어를 저장합니다. 같은 브라우저와 주소로 다시 열면 쿠키를 통해 이어 할 수 있습니다. 로컬 저장 모드는 개발 서버 한 프로세스에서 사용합니다.

기본 속도는 **실제 30초당 게임 내 1주**이며, 직접·자동 육성에 동일하게 적용됩니다. 훈련 화면의 타이머 옆 **x2** 버튼을 켜면 15초당 1주로 진행하며, 다시 누르면 기본 속도로 돌아갑니다. 선택은 서버에 저장되며 배속 전환 시 쌓인 진척을 유지합니다. 예전 x3·x4·x8 등의 배속 설정은 적용하지 않습니다. 로컬 개발용 `WEEK_MS`는 기준 주간 시간을 조정할 수 있습니다. 로컬 기록과 운영 규칙 도입 전 기록은 공식 종합 순위 대상에서 구분합니다.

- 직접 육성: 주차 시작에 훈련·휴식·치료를 고르고 **선택하고 이번 주 시작**을 누르면 30초 수행이 시작됩니다. 선택 전에는 시간이 쌓이지 않고, 시작한 행동은 그 주가 끝날 때까지 고정됩니다. 행동 결과 확인 → 이벤트 선택 → 대회 → 다음 주 행동 선택으로 이어집니다.
- 자동 육성: AUTO ON은 주간 행동·이벤트 선택·대회 출전·하이라이트·시상식·결과 확인·다음 주까지 모두 자동으로 진행합니다. 주간 행동은 시작 시 확정하고, 도중 전략 변경은 다음 주부터 적용합니다. AUTO OFF로 직접 육성으로 돌아갈 수 있습니다.
- 대회: 해당 주차에 출전 종목을 선택할 수 있습니다. 출전 종목을 누른 순서대로 체력을 쓰며, 저장한 루틴이 없으면 연계형 루틴을 사용합니다. 전체 60초 재생, 하이라이트, 즉시 결과를 지원합니다.
- 라이더는 연간 6개 대회에 출전할 수 있습니다. 52주가 지나면 새 시즌이 열리고, 8년차 페스티벌 주차가 끝나면 자동 은퇴합니다. 선수 정보에서 조기 은퇴도 가능하며, 기록을 보관한 뒤 새 선수를 등록할 수 있습니다.

## 인게임 화면

게임은 화면 높이를 사용하는 단일 프레임입니다. 하단 메뉴로 훈련·기술·대회·상점·전체 메뉴를 열고, 프레임 안에서 루틴·선수·계정·명예의 전당까지 이용합니다. 긴 일지는 상단 버튼의 보조 창으로 분리했습니다. 공통 댄싱·트릭 설명은 사용자가 지정한 [보드를 타보자!](https://minilongboard.vercel.app/) 도감을 참고해 보완했으며, 이 게임의 성장·점수 규칙은 별도로 유지합니다.

## Neon 연결

1. `neon.ts`는 Lakebase Postgres를 사용하는 구성입니다. `neon deploy`로 현재 브랜치의 `DATABASE_URL`, `DATABASE_URL_UNPOOLED`를 `.env.local`로 가져옵니다. 기존 파일은 연결 정보를 보존하며 수정합니다. 애플리케이션은 pooled URL, 마이그레이션은 direct URL을 사용합니다. `DATABASE_DIRECT_URL`이 있으면 마이그레이션에 우선 적용합니다.
2. 대상 브랜치를 확인한 뒤 프로젝트 루트에서 `npm run db:migrate`를 실행합니다. `drizzle/`의 SQL과 저널을 사용합니다. 스키마를 추후 변경하는 경우 `npm run db:generate`로 새 마이그레이션을 생성하고 SQL을 검토합니다.
3. `npm run dev`를 재시작하고 상단에 **NEON 저장**이 표시되는지 확인합니다. 새 라이더를 등록해 브라우저 새로고침과 서버 재시작 뒤 복구되는지 확인하세요. 로컬용 파일에 저장한 게스트는 Neon으로 자동 이관되지 않습니다.

연결 문자열은 서버에만 설정합니다. `VITE_` 접두사를 붙이지 마세요. 게스트는 브라우저 쿠키에 연결되어 있어 쿠키를 삭제하거나 다른 브라우저를 사용하면 자동 복구되지 않습니다. 기존 게스트 기록은 DB에 남습니다.

## Vercel 설정

프로젝트의 Framework Preset은 **Vite**, Build Command는 `npm run build`, Output Directory는 `dist`입니다. `vercel.json`은 Fluid compute를 활성화합니다. `/api/game`은 Node.js Vercel Function이며 서버 환경변수 `DATABASE_URL`과 32자 이상의 `AUTH_RATE_SECRET`을 사용합니다. 계정 인증 시도 제한은 이 서버 전용 비밀값으로 클라이언트 주소를 해시합니다. `pg` 풀과 `attachDatabasePool`이 연결 수와 종료 시점을 관리합니다. Preview와 Production에 해당 Neon 브랜치의 값을 각각 설정합니다. 배포 빌드는 DB 마이그레이션을 실행하지 않습니다. 대상 브랜치에 마이그레이션이 적용된 상태에서 배포하고, 등록 → 저장 → 재접속을 확인하세요.

## 검증과 구조

```sh
npm test
npm run build
```

- `src/game/`: 기술·스팟·이벤트·밸런스 설정, 시드를 사용하는 훈련과 경기 엔진. NPC에도 선수와 같은 경기 엔진을 적용합니다.
- `src/scene/`: 절차적으로 생성한 원본 도트 배경과 스프라이트. 경기 결과 로그가 재생을 구동합니다.
- `server/`, `api/`: 서버 발급 게스트 세션, 런타임 입력 검증, Drizzle 저장소. 세션 토큰은 DB에 해시로 저장합니다. 커리어 JSONB 한 건에 스탯, 기술, 이벤트, 대회, 시즌, 은퇴 기록을 담고, 버전이 일치할 때만 원자적으로 갱신합니다.
- 주간 진행은 브라우저 페이지의 주기적 요청으로 처리합니다. 이미 등록된 페이지는 백그라운드에서 지연된 시간을 다음 요청에 반영합니다. 페이지를 새로 열면 이전 페이지가 닫혀 있던 시간을 추가하지 않습니다. 갑작스러운 종료로 마지막 요청이 전송되지 않은 경우 마지막으로 서버가 확인한 진척까지만 보존됩니다.

## 2차 콘텐츠

- 야간 광장과 대회 연습장의 해금 조건은 육성 홈에 표시됩니다. 실내·야간·대회 연습장에서 지정 기술에 집중 레슨을 추가할 수 있습니다. 대회 연습장의 루틴 리허설은 선택한 종목의 저장 루틴을 사용합니다.
- 기술 도감에서 29개 기술의 선행 조건과 예상 성공률, 도트 미리보기를 볼 수 있습니다. 자동 육성 설정에서 중요한 이벤트 일시 정지를 켜면 라이벌전과 일부 기술 지도에서 선택을 기다립니다.
- 장비·스폰서에서 데크·트럭·휠·베어링을 구매하고 장착하거나 판매할 수 있습니다. 계약은 시즌당 한 곳이며, 해당 시즌 대회에서 협찬 종목으로 입상하면 다음 시즌 계약이 갱신됩니다.
- 대회 결과에서 선수별로 전체 관람과 하이라이트를 재생할 수 있습니다. 1차 경기 기록은 당시 저장한 플레이어 로그로 재생됩니다. 재생은 저장된 경기 로그를 사용하고 보상을 지급하는 시점은 경기 확정 시점입니다.
- 기존 PostgreSQL 테이블은 동일합니다. 커리어 JSONB에 새 필드를 추가했고, 1차 저장에 없는 필드는 기본값으로 읽습니다. 기존 선수와 기술, 점수, 입상 기록을 변환하는 SQL 단계가 필요하지 않습니다.

기술 설명은 롱보드 스텝 및 프리스타일 용어를 참고했습니다. [Simple Longboards](https://www.simplelongboards.com/classic-videos) · [롱보드 댄싱·프리스타일 용어 사전](https://cdn.hs-heilbronn.de/1ab3cb8526054e7a/2c85a03225b2/BuchmannSchramm_Dictionary_LDF_2025-01-29.pdf)

## 3차 커리어와 온라인 기능

대회 출전 선택 → 종목별 관람 → 점수 발표·시상식 → 육성 계속과 이벤트 대화·선택지, 부상 확인은 육성 홈의 도트 게임 화면 안에서 진행합니다. 대회 일정은 일정·기록 조회용이며 과거 경기도 게임 화면에서 다시 봅니다. 대회 결과 확인 중에는 서버가 주간 진행을 멈추고 새로고침 후에도 미확인 결과를 복구합니다. 직접 육성은 **육성 계속**을 누르면 다음 행동을 기다리며, 자동은 관람·시상식 뒤 확인까지 처리하고 다음 주를 시작합니다.

- 8년차 페스티벌 결과와 보상을 확정한 뒤 은퇴 기록을 생성합니다. 레전드, 종목별 챔피언, 테크니션, 베테랑, 조기 은퇴 엔딩과 라이벌 에필로그를 지원합니다. 개인 명예의 전당에서 은퇴식을 다시 볼 수 있습니다.
- 계정은 로그인 아이디와 비밀번호를 사용합니다. 이메일을 수집하지 않으며 이메일 기반 비밀번호 복구 기능은 없습니다. 게스트 기록을 계정에 연결하고, 양쪽에 현역 선수가 있을 때는 한 명을 보관함에 둡니다. 계정 생성과 로그인은 세션을 교체합니다.
- 은퇴 선수는 기본 비공개입니다. 공개·철회, 다른 선수의 공개 프로필 조회, 이름 앞부분 검색, 부문·엔딩·완주 필터, 페이지네이션을 지원합니다. 계정 삭제는 관련 커리어, 세션, 공개 프로필, 순위와 신고 데이터를 삭제합니다.
- 공식 순위는 서버에 남긴 경기 입력과 시드로 결과를 재현해 검증합니다. 8년 종합 점수에는 부문·메이저·시즌 챔피언 가중치를 적용합니다. 기존 검증 근거가 없는 경기는 개인·공개 프로필에 보존하고 공식 점수와 구분합니다.
- 같은 계정의 은퇴 선수가 새 회차의 선배로 등장합니다. 이전 스탯과 기술 숙련도는 상속하지 않습니다. 자동은 중요한 이벤트·대회·부상 확인도 선택하며 계속 진행합니다.
- `0001_military_leopardon.sql`은 기존 세 테이블에 계정·공개 프로필·랭킹·신고·인증 제한·로컬 이관 이력 테이블을 추가합니다. 기존 커리어 스냅샷을 보존합니다. 로컬 모드는 같은 SQL 마이그레이션을 PGlite에 적용하고, 기존 파일 저장은 유효한 게스트 쿠키로 처음 접속할 때 한 번 가져옵니다.

## 검증과 운영

`npm run simulate -- 12`는 전략마다 12개 시드로 8년 전체를 반복 검증하는 내부 도구입니다. 플레이 화면에 시간 단축 기능을 추가하지 않습니다.

`npm run verify:neon -- http://127.0.0.1:5185`는 해당 로컬 서버가 Neon을 사용하는지 확인하고 훈련·저장·계정 연동·장비·은퇴·공개·철회·재로그인을 실제 HTTP 요청으로 검증합니다. 이 검증은 전용 임시 계정을 만들고 종료 시 해당 계정의 데이터를 정리합니다. 빠른 확인에는 검증 서버를 `WEEK_MS=4800`으로 시작합니다.

`npm run verify:neon -- https://배포주소.vercel.app --deployed`로 배포된 앱도 동일하게 검증합니다. 운영의 실제 30초 훈련 시간을 기다리며, 페이지와 빌드 자산 응답도 확인합니다. `npm run build`는 브라우저 코드와 Node.js 서버 코드의 모듈 해석을 각각 검사합니다.

신고 검토와 비공개 처리는 [운영 절차](docs/operations.md)를 따릅니다. 공개 이름에는 최소한의 금칙어 검사와 사용자 신고를 적용합니다. 신규 표현의 판단에는 운영자 검토가 필요합니다. 실시간 멀티플레이, 3D, 생성형 NPC 대화, 결제와 커뮤니티 기능은 이번 범위에서 제외했습니다.
