# 롱보더 키우기 운영

## 저장과 마이그레이션

현역 선수, 개인 은퇴 기록과 경기 재현 입력은 브라우저의 IndexedDB에 저장합니다. Neon `board2`의 PostgreSQL에는 명예의 전당 계정, 공개 프로필, 순위와 신고를 저장합니다. 예전 `rider_careers.snapshot`은 이전 배포의 복구에 사용합니다.

1. 대상 Neon 프로젝트와 브랜치를 확인합니다.
2. 운영 변경 전 복구 시점 또는 별도의 Neon 브랜치로 현재 상태를 보관하고, 동일 마이그레이션을 검증합니다.
3. direct 연결인 `HALL_DATABASE_DIRECT_URL`로 `npm run db:migrate`를 실행합니다.
4. 브라우저의 커리어 재개와 board2의 공개 프로필 조회를 확인합니다.

이미 처리한 대회 결과나 은퇴 기록을 수동 편집하면 공식 순위 재현에 영향을 줄 수 있습니다. 복구는 데이터 전체와 마이그레이션 이력, 해당 릴리스의 규칙 버전을 함께 맞춥니다. Neon 복구 브랜치를 만든 뒤 일부 계정의 데이터를 확인하고 연결 대상을 전환합니다. 복구 보존 기간은 Neon 프로젝트 정책에 따릅니다.

## 신고 검토

운영자만 접근할 수 있는 SQL 콘솔에서 최근 신고를 확인합니다.

```sql
SELECT r.public_id, r.reason, r.created_at, p.profile->>'name' AS rider_name
FROM rider_reports r
JOIN public_riders p ON p.id=r.public_id
ORDER BY r.created_at DESC
LIMIT 50;
```

공개 내용에 문제가 확인된 경우 대상 공개 프로필 ID를 파라미터로 지정해 `public_riders.hidden=true`로 설정합니다. 목록·상세·글로벌 순위 조회가 이 필드를 검사합니다. 사용자가 공개를 다시 눌러도 운영 비공개 상태가 유지됩니다. 검토가 끝난 뒤 해제할 때는 같은 대상의 `hidden=false`를 설정합니다. 철회된 프로필은 `active=false`가 유지되어 사용자 재공개 전까지 나타나지 않습니다.

## 계정과 개인정보

명예의 전당은 로그인 아이디, scrypt 비밀번호 검증값, 만료되는 세션 해시와 공개 게임 기록을 저장합니다. 인증 시도 제한용 주소 값은 `AUTH_RATE_SECRET`으로 해시하여 최대 10분 단위로 집계합니다. 계정 삭제는 세션, 공개 프로필, 순위 및 그 계정이 제출한 신고를 삭제합니다. 소유자의 공개 프로필이 삭제되면 그 프로필에 접수된 신고도 삭제됩니다.

이메일 기반 복구를 지원하지 않습니다. 데이터베이스 복구본에 포함된 삭제 데이터의 보존은 Neon 보존 정책을 따릅니다. 과거 시점으로 복구할 때 삭제 요청과 공개 철회가 되돌아가지 않았는지 확인합니다.

## 오류와 로그

API는 저장 실패 시 일반화된 메시지와 503을 반환합니다. 연결 문자열이나 비밀번호를 로그에 기록하지 않습니다. Vercel 함수 로그에서 저장 실패 시각을 확인한 뒤 Neon 연결·컴퓨트 상태와 마이그레이션 이력을 점검합니다. 일시적인 요청 충돌은 최신 커리어를 불러오고 사용자의 선택을 다시 받습니다.

대회가 확정되면 저장 스냅샷의 `clock.pendingMeet`에 확인할 경기 키를 저장합니다. 경기 재생과 시상식은 이미 확정된 로그를 보여 주며 보상을 다시 지급하지 않습니다. 결과 확인 전에는 주간 진행과 추가 게임 명령을 막고, 일치하는 경기 키로 `continue-meet`을 처리한 뒤 새 시계를 시작합니다. 새로고침과 다른 탭에서도 같은 대회가 복구됩니다.

운영 API는 서버 시간으로 기본 2초를 한 주로 계산합니다. 브라우저가 완전히 종료된 동안에는 육성을 진행하지 않습니다.

## 주차 선택과 동시 저장

직접 육성은 행동 선택 전 시간을 누적하지 않습니다. 행동 시작 시 시계를 초기화하고 해당 주 계획을 고정합니다. 수행 후 `clock.pendingTraining`을 결과 확인으로 사용하며, 확인 전에는 다음 행동을 처리하지 않습니다. 자동은 매주 계획을 확정하고 이벤트·대회·결과·다음 주로 이어집니다.

각 탭은 요청에 사용한 저장본과 현재 IndexedDB에 있는 저장본이 같을 때만 결과를 저장합니다. 다른 탭이 먼저 저장한 경우 최신 커리어를 불러오고 선택을 다시 받습니다.
