# 장비 개편 적용 검토

## 저장 구조와 적용 범위

실제 운영 DB를 읽기 전용으로 확인했다. 현재 장비 데이터는 별도 장비 테이블이 아니라 `rider_careers.snapshot` JSONB의 선수별 `extras.inventory`와 `extras.equipped`에 들어 있다. 다른 게임 상태와 한 번의 버전 비교 저장으로 갱신하는 현재 구조를 유지한다. 테이블 삭제·스키마 변경·운영 SQL 일괄 갱신은 하지 않는다.

아이템 마스터는 기존처럼 브라우저와 서버가 공유하는 버전 관리 데이터다. `src/game/equipmentCatalog.ts`에 새 장비 22종과 액세서리 30종을 등록했다. 기존 9종의 ID는 별도로 보존한다. 사용자 보유 목록, 기본 장비 장착 상태, 액세서리 3칸은 마스터와 분리한다. 신규 선수의 기본 3종 지급과 기존 선수 변환은 중복 실행해도 같은 결과를 낸다.

## 기존 저장 형식 변환

- `equipmentVersion: 2`를 저장한다. 현재 버전의 기록은 다시 변환하지 않는다.
- 기존 아이템 ID와 보유 목록을 보존한다. 신규 기본 데크·트럭·휠이 없으면 한 번 지급한다.
- 기존 베어링은 ID·이름·호환 효과를 유지하며 액세서리로 옮긴다. 새 `acc_011`과 합치지 않는다.
- 알 수 없는 장비와 슬롯 초과 아이템도 보유 기록 및 `legacyEquipment` 원본에 남긴다. 검증할 수 없는 효과는 합산하지 않는다.
- 기본 능력치, 보유금, 과거 경기 입력과 은퇴 기록을 다시 쓰지 않는다.
- GET 응답의 변환은 읽기용이다. 운영 적용을 승인한 뒤 배포하면 선수의 다음 정상 저장에서 해당 선수의 새 장비 형식이 저장된다. 보관 선수는 전환 후 다음 저장 시 처리한다.
- 예전 공식 경기는 당시 규칙 1·2와 기존 장비 효과로 재검증한다. 새 경기만 규칙 3과 새 장비/액세서리 입력을 보관한다.

## 기본 스탯과 효과

영구 성장값은 `rider.stats`에만 저장한다. 데크는 연계·밸런스, 트럭은 카빙, 휠은 속도를 별도로 더한다. 현재 스탯 표시와 새 경기 계산은 `effectiveStats()`를 사용하며, 경기 입력에는 기본값과 장비 정보를 각각 보관해 두 번 더하지 않는다. 훈련으로 얻은 영구 성장에는 장비 스탯을 섞지 않는다.

액세서리는 데이터로 정의된 회복·소모·숙련·관계·명성·상금·이벤트 효과를 사용한다. 부상 감소는 합계 2%p, 대성공 1%p, 숙련·성장 6%, 상금·명성 6% 등 상한을 두었다. 장식·파티클·코믹 반응은 채점 입력을 바꾸지 않는다. 자동 육성은 사용자의 장착 상태를 유지하고 구매·교체하지 않는다.

## 검증과 운영 승인

`npm test`, `npm run build`, `npm run review:equipment`로 로컬 동작을 확인한다. `npm run db:inspect-equipment`는 운영 기록에 대한 변환을 메모리에서 검증하며 트랜잭션을 READ ONLY로 제한한다. 실제 운영 기록의 형식을 바꾸는 배포는 요청서의 승인 조건에 따라 별도 승인을 받은 뒤 진행한다.

2026-11-18 검증 결과: 전체 테스트 36개 및 빌드 통과. 격리된 로컬 PostgreSQL과 HTTP API에서 중복 구매 방지, 기본 3종 지급, 액세서리 3칸, 저장 복구, 실제 훈련, 자동 대회, 판매를 확인했다. 기존 배포 엔진과 비교한 과거 경기 648건이 동일했다. 운영 읽기 전용 검사에서 베어링 장착 기록 1건의 변환을 검증했고, 미확인 장비·슬롯 초과·DB 쓰기는 모두 0건이었다.
